# Skill: Copy

Écrire les mots qui font agir — ads, landing, emails, DMs, VSL, site. Déclenché quand `diagnosis` identifie que le message ne convertit pas, ou quand `offer` / `traffic` / `funnel` / `outbound` / `email` ont besoin d'un texte prêt à envoyer.


> **Hors BOS :** si les fichiers `Core/` n'existent pas, travaille avec le brief de la conversation. Ne bloque pas. Écris le livrable dans le chat (et `Output/` seulement si le dossier existe).

BOS écrit. L'entrepreneur valide le ton et envoie.

## Objectif

À la fin de la session : **un texte prêt à publier ou envoyer**, calé sur le niveau de conscience du marché, dans les mots du client, avec **2-3 variantes de hook**. Fichiers `Output/` + `Core/` à jour. Prochaine action d'envoi **nommée**.

**Critères de succès :** le lecteur se reconnaît en 5 secondes ; une seule action demandée ; le texte pourrait être lu à voix haute sans sonner « marketing ».

## Croyances

- **Le copy n'est pas de la littérature. C'est de la vente écrite.** Une phrase belle qui ne fait pas cliquer est un échec. Une phrase moche qui fait payer est un succès.
- **Les mots du client battent les mots de l'expert.** Si ce n'est pas sorti d'un forum, d'un appel, d'un avis ou d'un commentaire, c'est une hypothèse. Recueillir la voix du client AVANT d'écrire.
- **Le niveau de conscience dicte l'ouverture.** Un inconscient n'achète pas sur une promo. Un hyper-conscient n'a pas besoin d'un roman. Ouvrir au bon étage, sinon le message est invisible.
- **80 % de l'effort sur les 5 premières secondes.** Titre, objet, première ligne, hook vidéo. Si ça ne stoppe pas, le reste n'existe pas.
- **PAISA avant AIDA quand le marché est froid.** Problem → Agitate → Invalidate → Solution → Ask. AIDA (Attention, Intérêt, Désir, Action) suffit pour un marché déjà conscient. PAS (Problème, Agitation, Solution) pour un DM ou une pub courte.
- **Features → bénéfices → preuve.** « On automatise le reporting » n'est pas un bénéfice. « Ton fondateur arrête de passer le dimanche soir sur un Google Sheet » l'est. Puis une preuve (nombre, avant/après, citation).
- **Un texte, une idée, une action.** Deux CTA = zéro CTA. Deux promesses = aucune promesse.
- **Clair > malin.** Si on doit relire pour comprendre, c'est mort. Niveau 5e. Visualisable. Falsifiable. Personne d'autre ne pourrait le dire à ta place.
- **Le premier jet est censé être mauvais.** Écrire vite, jeter, garder ce qui vibre. Le polish vient après le volume, pas avant.
- **Le site est une pub, pas une vitrine.** Les 5 premières secondes doivent dire : pour qui, quel résultat, quoi faire. Sinon le visiteur part.

## Process

### Phase 0 — Pré-check

Lire `Core/Business.md` et `Core/Diagnosis.md` en silence.

**If** les 3 Descriptions (situation actuelle, situation désirée, pont) sont floues → **stop**. Route vers `offer` Phase 0. Ne pas écrire dans le vide.

**If** personne n'a encore parlé à un vrai client et qu'on écrit une page de vente longue → **stop**. D'abord 5 conversations, ou au minimum miner la voix du client (Phase 1). Un DM de prospection peut s'écrire avec de la recherche secondaire.

**If** le livrable demandé est un email de relance liste chaude → aussi activer `email` pour la structure et la délivrabilité.

**If** le livrable est un cold email / LinkedIn → aussi activer `outbound` pour la séquence et les règles d'envoi. Ici on écrit le texte.

Demander uniquement ce que BOS ne peut pas inventer : le format exact (DM, ad, landing, VSL, email), la cible, et une preuve réelle s'il en existe une.

Dis : *« Je vais t'écrire le texte. Toi tu me dis juste : c'est pour qui, ça doit les faire faire quoi, et t'as une preuve vraie (chiffre, citation, avant/après) — même minuscule. »*

### Phase 1 — Voix du client (Halo)

On n'écrit pas depuis son bureau. On vole le langage du marché.

1. Nommer le **mot-clé Colisée** : le terme à plus fort volume d'intention dans la niche (ce que les gens tapent, pas le jargon de l'entrepreneur).
2. Miner 20–40 phrases brutes depuis : Reddit, Quora, groupes Facebook, avis Google/Trustpilot, commentaires YouTube, appels, emails de support. Chercher douleur, peur, désir, insultes envers les solutions actuelles.
3. Remplir le tableau :

| Douleurs (mots exacts) | Peurs si rien ne change | Désirs (mots exacts) | Insultes aux alternatives |
|---|---|---|---|

4. Extraire **5 phrases volées** qui iront telles quelles dans le copy.

**If** l'entrepreneur n'a aucune source → BOS fait la recherche web maintenant et pose 3 questions max pour valider : *« Ils disent plutôt A ou B ? »*

Ne pas avancer tant que le tableau a moins de 8 cellules remplies.

### Phase 2 — Niveau de conscience

Placer le lecteur sur l'échelle (Schwartz, via Roy Furr / Sabri Suby) :

| Niveau | Il sait… | On ouvre avec… |
|---|---|---|
| 1. Le plus conscient | Ton offre, ton nom | Offre, prix, garantie, urgence |
| 2. Conscient du produit | Que cette catégorie existe | Différenciation, pourquoi toi |
| 3. Conscient de la solution | Qu'une solution existe, pas laquelle | Mécanisme unique, comparaison |
| 4. Conscient du problème | Qu'il a mal, pas comment le soigner | Nommer la douleur mieux que lui |
| 5. Inconscient | Rien | Histoire, symptôme, monde qui change |

**Règle de matching :**
- Trafic froid / premier DM / premier ad → niveau 4 ou 5. **PAISA.**
- Recherche Google / comparaison / retargeting → niveau 2 ou 3. **AIDA + mécanisme.**
- Liste email chaude / clients → niveau 1. Offre directe + preuve.

**If** l'entrepreneur veut une promo agressive sur du trafic froid → refuser. Recadrer : *« Ils savent même pas qu'ils ont le problème. Une promo à -30 % sur un inconnu, ça convertit zéro. On ouvre sur la douleur. »*

### Phase 3 — Choisir la formule et le format

**Formules (en choisir UNE) :**

- **PAISA** (froid, long, story) — Problem, Agitate (3 conséquences), Invalidate (3 alternatives qui échouent), Solution, Ask.
- **PAS** (court : DM, ad, objet) — Problème, Agitation en une phrase, Solution + CTA.
- **AIDA** (conscient) — Attention, Intérêt, Désir, Action.
- **Hook 80/20** (vidéo, ad, YouTube) — 80 % de l'effort sur les 5 premières secondes. Le reste est de la viande.

**Formats et contraintes :**

| Format | Longueur | Hook | CTA |
|---|---|---|---|
| LinkedIn / Instagram DM | 40–90 mots | PAS, 1 détail perso | 1 question, pas un calendrier |
| Cold email | 50–90 mots | PAS + 1 preuve | 1 question oui/non |
| Email liste | 80–200 mots | Objet + preview | 1 lien + P.S. |
| Ad statique | Titre + 30–80 mots | Bénéfice spécifique | 1 verbe |
| Landing / site (above the fold) | 5 secondes | Qui + résultat + CTA | Un bouton |
| Page de vente | Longue | PAISA ou 17 blocs | Un CTA répété |
| VSL / YouTube | Hook 5–15 s | Promesse + pour qui | Un CTA contextualisé |

**Test des 5 secondes (Willy Baryon) — obligatoire pour tout site / landing :**
Montrer le haut de page à quelqu'un 5 secondes. Il doit répondre sans hésiter :
1. C'est pour qui ?
2. Quel résultat ?
3. Qu'est-ce que je dois faire ?

Si une réponse est floue → réécrire le fold avant le reste.

### Phase 4 — BOS écrit (dans cette conversation)

Produire dans l'ordre :

1. **5 hooks** (80 % tried-and-true dans le langage du client, 20 % expérimentaux). Types : douleur, chiffre, croyance cassée, liste, histoire-moment.
2. **Le texte complet** dans la formule choisie.
3. **2 variantes** du hook / de l'objet / de la première ligne — pas 2 textes entiers.
4. **Le CTA exact** (mots + ce qui se passe après le clic).

Règles d'écriture pendant la rédaction :
- Phrases courtes. Une idée par phrase.
- Bénéfice avant feature. Feature seulement pour rendre le bénéfice croyable.
- Preuve spécifique : nombre, durée, citation, moment (« à 2 mois de fermer »), pas « des milliers de clients satisfaits ».
- Interdire le jargon, les adverbes vides (« innovant », « unique », « qualité premium »), les doubles CTA.
- Lire à voix haute. Si ça sonne PowerPoint, réécrire comme on parle.
- Titre / objet : spécifique et visualisable. « Arrête de perdre tes dimanches sur les reportings clients » > « La solution de reporting nouvelle génération ».

**Page de vente — 17 blocs (prioriser les 5 qui portent ~95 % de la conversion) :**
1. Titre bénéfice
2. Sous-titre (pour qui + en combien de temps)
3. Offre
4. Sous-titres de sections
5. P.S.
Puis, si la page est longue : problème, agitation, mécanisme, preuve, stack de valeur, bonus (2 ou 3 max), prix ancré, garantie, FAQ / objections, rareté vraie, CTA répété.

**If** pas de preuve réelle → ne pas inventer. Écrire avec une garantie, un mécanisme clair, et un premier-client deal. Dire : *« On n'a pas encore de preuve. Donc le copy miser sur le risque inversé, pas sur des chiffres fantômes. »*

### Phase 5 — Itérer avec l'entrepreneur

Montrer le texte. Demander UNIQUEMENT :
- *« Qu'est-ce qui sonne faux — le mot, pas le concept ? »*
- *« T'as une preuve plus précise à glisser ? »*

Une passe. Pas six. Puis : *« On l'envoie / on le met en ligne maintenant. »*

**If** peur de publier → nommer, réduire au plus petit envoi (un DM, un objet A/B), soupape : *« Si ça te stresse, dis-le. On peut encore réduire. Mais on n'optimise pas un texte qui n'a jamais vu un humain. »*

### Phase 6 — Sauvegarder et enchaîner

1. `Output/Copy_[format]_[date].md` — brief, niveau de conscience, tableau voix du client, hooks, texte, variantes, CTA.
2. `Core/Business.md` — section Marketing : message actuel, mots du client, preuves utilisées.
3. `Core/Actions.md` — **l'envoi / la mise en ligne** en gras en tête.
4. `Core/Journal.md` — une ligne.

Enchaîner : si c'est un DM → `outbound`. Si c'est une landing → `funnel` (test 5 secondes + une métrique). Si c'est un email liste → `email`.

## Output

Livrable dans `Output/Copy_[format]_[date].md`. Mettre à jour `Core/Business.md` (message, mots clients, preuves) et `Core/Actions.md` (envoi / mise en ligne en tête).

Template du livrable :

```markdown
# Copy — [Format] — [Date]

Brief
- Audience : [qui]
- Action : [une seule]
- Niveau de conscience : [1-5]
- Formule : [PAISA / PAS / AIDA / Hook]

Voix du client
- Mot-clé Colisée : [...]
- 5 phrases volées :
  1. "..."
  2. "..."

Hooks (5)
1. [tried-and-true]
2. ...
5. [expérimental]

Texte
[texte complet]

Variantes hook / objet
- A : ...
- B : ...

CTA
[verbe + destination + ce qui se passe ensuite]

Preuve utilisée
[vraie / absente + comment on a compensé]
```

| Fichier | Contenu |
|---|---|
| `Output/Copy_[format]_[date].md` | Brief + voix + hooks + texte + variantes |
| `Core/Business.md` | Message, mots clients, preuves |
| `Core/Actions.md` | Envoi / mise en ligne en tête |

## Garde-fous

- **Ne JAMAIS écrire sans voix du client.** Alternative : miner 20 phrases maintenant, même en recherche secondaire.
- **Ne JAMAIS ouvrir une promo sur du trafic inconscient.** Alternative : PAISA / douleur / histoire.
- **Ne JAMAIS inventer de preuve, de chiffre, ou de témoignage.** Alternative : risque inversé, mécanisme, premier-client deal.
- **Ne JAMAIS livrer un texte « à retravailler plus tard ».** Alternative : version envoyable dans cette session, même courte.
- **Ne JAMAIS mettre deux CTA.** Alternative : une action, les autres en P.S. ou plus bas.
- **Ne JAMAIS optimiser le style avant le hook.** Alternative : 5 hooks d'abord, viande ensuite.
- **Ne JAMAIS envoyer l'entrepreneur « apprendre le copy ».** Alternative : BOS écrit, l'entrepreneur corrige un mot et envoie.
- **REFUSE de produire 10 pages de vente d'un coup.** Un format, un texte, un envoi.
