# Skill: Foundation

Poser le socle avant la première pièce de copy, quand l'entrepreneur n'a jamais écrit pour vendre. Déclenché une fois, puis on passe à `bigidea` et `copy`. Source : cours débutant d'Umar Tazkeer.

## Objectif

Fin de session : **un persona**, **trois features traduites en bénéfices**, et **une pièce courte** (email ou hero) qui fait agir. Fichier `Output/Foundation_[date].md`.

**Critères de succès :** on distingue le copy du contenu. Le persona existe avant le texte. Aucun « mot puissant » n'est là pour compenser une offre vide.

## Croyances

- **Le copy fait agir. Le contenu informe.** Un article intéressant qui ne demande rien n'est pas du copy. On ne se félicite pas d'avoir « posté ».
- **Les mots puissants ne sauvent pas une offre faible.** On les ajoute à la fin, ou pas.
- **Besoin et désir ne sont pas la même phrase.** Le besoin est le problème. Le désir est la scène une fois le problème fini. Les deux apparaissent.
- **Chaque feature devient un bénéfice vécu.** « Rapport automatique » ne veut rien dire tant qu'on n'a pas dit ce que la personne n'a plus à faire.
- **Le persona s'écrit avant le texte.** Sans lui, la personnalisation est du prénom dans un mail générique.
- **AIDA est le minimum d'une pièce courte.** Attention, intérêt, désir, action. Pas un framework de plus par-dessus.
- **Une landing tient en trois.** Promesse, preuve, action.

## Process

### Phase 0 — Est-ce le bon skill

**Si une big idea et un persona existent déjà →** ne pas refaire le socle. Aller à `copy`.

**Si l'offre n'existe pas →** `offer`. Le socle n'invente pas le deal.

### Phase 1 — Persona

Cinq lignes : qui décide, symptôme cette semaine, déjà essayé, peur si rien ne change, mot qu'il utilise.

### Phase 2 — Trois bénéfices

Prendre trois features réelles. Pour chacune : « donc tu [scène concrète] ».

Écrire aussi une ligne de besoin et une ligne de désir. Si elles disent la même chose, le désir est encore une feature.

### Phase 3 — Pièce courte

Choisir un format :

- **Hero.** Promesse, preuve ou absence honnête de preuve, action.
- **Email.** Sujet, une idée, un CTA.

Structure AIDA visible. Puis couper les adjectifs qui ne changent pas le sens.

### Phase 4 — Passer la main

La pièce suivante, plus ambitieuse, ne reste pas ici. `bigidea` puis `page`, `email` ou `copy`.

## Output

```markdown
# Socle copy — [date]

## Persona
## Besoin / désir
## 3 bénéfices
## Pièce
```

| Fichier | Contenu |
|---------|---------|
| `Output/Foundation_[date].md` | Persona, bénéfices, pièce |
| `Core/Business.md` | Persona si absent |

## Garde-fous

- **Ne JAMAIS traiter ce skill comme le système complet.** → Une fois le socle posé, on sort.
- **Ne JAMAIS empiler les power words sur une offre floue.** → `offer`.
- **Ne JAMAIS appeler « copy » un post qui n'a pas d'action.** → Ajouter l'action ou le classer contenu.
- **REFUSE une deuxième session de socle.** → La suite est une vraie pièce.
